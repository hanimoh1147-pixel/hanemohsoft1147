# HaneSoftwer — نسخة المشروع الأساسية (بدء التنفيذ)

هذه نسخة تطوير أولية مبنية على مواصفات HaneSoftwer. الواجهة عربية RTL وتصميمها أسود وذهبي ومتجاوب مع الهاتف. تعتمد على Supabase للمصادقة وقاعدة البيانات والتخزين. **هذه ليست منصة منشورة أو جاهزة للإنتاج بعد**؛ يلزم تطبيق SQL واختبار المشروع وربط النطاق ومزود الدفع قبل تشغيله مع العملاء.

## ما تم تجهيزه في هذه النسخة

- تغيير الاسم الظاهر إلى **HaneSoftwer**.
- تسجيل حساب بالبريد وكلمة المرور، وتسجيل دخول بالبريد وكلمة المرور.
- تسجيل الدخول باسم المستخدم وكلمة المرور عبر Supabase Edge Function مرفقة.
- ملف عميل يعرض الرتبة والرصيد.
- نظام رتب من نجمة إلى خمس نجوم، مع ترقية تلقائية حسب عدد الطلبات المكتملة، وتثبيت/تعديل يدوي من الأدمن.
- شاشة للأدمن لتعديل شروط الترقية التلقائية.
- أسعار خاصة لكل رتبة ولكل خدمة، مع تحقق السعر النهائي داخل دالة قاعدة البيانات عند إنشاء الطلب.
- رقم فريد لكل طلب بصيغة `HSW-YYYYMMDD-000001`.
- نموذج طلب يتضمن اسم العميل، رقم الهاتف، موديل الجهاز، IMEI، SN، وتفاصيل المشكلة.
- تحذير وإقرار موافقة إلزامي لخدمات JTAG/الجيتاج عند تصنيف الخدمة باسم JTAG أو جيتاج.
- سجل الطلبات وردود الأدمن وتحديث الحالات، مع استرداد تلقائي مرة واحدة عند إلغاء طلب غير مكتمل.
- صلاحية تمكين/تعطيل تحويل الرصيد لكل مستخدم من لوحة الإدارة، مع سجل تحويلات.
- شحن يدوي بالإيصال ومراجعة الأدمن.
- توضيح في الواجهة بأن بوابة الدفع الإلكترونية غير مفعلة حتى اختيار مزود وتهيئة مفاتيحه في الخادم.

## 1) تهيئة Supabase

1. افتح مشروع Supabase الصحيح.
2. من **SQL Editor** نفّذ الملف `schema.sql` كاملًا على قاعدة بيانات المشروع. إذا كان المشروع يحتوي بيانات مهمة، خذ نسخة احتياطية واختبر أولًا في مشروع تجريبي.
3. تأكد من إنشاء Storage bucket باسم `deposit-proofs` والسياسات الموجودة في `schema.sql`.
4. راجع إعدادات **Authentication → URL Configuration** بعد اختيار نطاقك، وأضف عنوان الموقع إلى Site URL وRedirect URLs.
5. افتح `config.js` وتأكد من `SUPABASE_URL` و`SUPABASE_ANON_KEY`. المفتاح العام/Publishable مسموح في الواجهة؛ **لا تضع service_role أو مفاتيح بوابة الدفع في هذا الملف أبدًا**.

## 2) تفعيل تسجيل الدخول باسم المستخدم

دالة Edge Function موجودة في:

`supabase/functions/username-login/index.ts`

من جهاز عليه Supabase CLI، داخل مجلد المشروع:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy username-login
```

تأكد أن بيئة الدالة تحتوي `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY`. إذا احتجت لإضافة المفتاح السري، أضفه إلى **Secrets الخاصة بالمشروع/الدوال** فقط. لا تضعه في `config.js` أو GitHub.

## 3) إعداد حساب المالك

1. أنشئ حسابًا من واجهة التسجيل.
2. من Supabase SQL Editor نفّذ الاستعلام التالي بعد استبدال البريد ببريد حساب المالك:

```sql
update public.profiles p
set role = 'owner',
    permissions = array['manage_services','review_deposits','manage_orders','manage_reviews']
from auth.users u
where p.id = u.id and lower(u.email) = lower('YOUR_OWNER_EMAIL');
```

نفّذ هذا يدويًا من لوحة Supabase فقط. لا تضف منطقًا يسمح للواجهة بتغيير `role` أو `permissions` أو `wallet_balance`.

## 4) النطاق والابتعاد عن إدخال IP يدويًا

الاسم المستهدف الذي طلبته هو **`hanesoftwer.com`**، لكن لم يتم شراء النطاق ولم يتم تأكيد توفره. يجب فحصه وتسجيله أولًا؛ فحص النطاق لا يحجزه. يمكنك البحث من خلال [Namecheap](https://www.namecheap.com/domains/domain-name-search/) أو [GoDaddy](https://www.godaddy.com/domains).

بعد امتلاك النطاق:

1. انشر ملفات الواجهة على Cloudflare Pages أو استضافة ثابتة مشابهة.
2. أضف النطاق من إعدادات الاستضافة واتبع سجلات DNS التي تعطيك إياها المنصة؛ لا تخمّن عناوين IP.
3. فعّل HTTPS وانتظر اكتمال إعداد DNS.
4. أضف النطاق نفسه إلى Supabase Authentication Site URL وRedirect URLs.

المستخدمون يفتحون الموقع بالاسم، وليس بإدخال IP. تقنيًا، DNS يوجّه اسم النطاق إلى البنية التحتية للاستضافة، لكنك لا تحتاج إلى إعطاء المستخدمين عنوان IP مباشرًا أو تثبيته داخل كود الموقع.

## 5) بوابة الدفع الإلكتروني

غير مفعلة في هذه النسخة. الشحن اليدوي يعمل عبر إضافة طريقة دفع، رفع الإيصال، ثم مراجعة الأدمن. لربط دفع آلي نحتاج أولًا اختيار مزود يدعم بلد التشغيل وطريقة الدفع المطلوبة؛ بعد ذلك تتم معالجة الدفع والتحقق من Webhook في دالة خادم، ولا تُقبل إشعارات الدفع من المتصفح وحده.

## 6) ملاحظات مهمة قبل الاستخدام الحقيقي

- محفظة هذه النسخة الأساسية بالدولار فقط. قاعدة البيانات تقبل بعض حقول العملات الأخرى، لكن تنفيذ الطلبات والتحويلات المالية بعملات متعددة **غير مفعّل** حتى بناء محافظ منفصلة وسعر صرف موثوق.
- الترقية التلقائية تعتمد على عدد الطلبات المكتملة: افتراضيًا 5، 15، 35، 75 للرتب 2–5. يمكن للأدمن تعديل الحدود من اللوحة. الحسابات المثبتة يدويًا لا تتغير تلقائيًا.
- أرقام الطلبات فريدة؛ السعر والرتبة المستخدمان في عملية الطلب يتم حسمهما في قاعدة البيانات.
- إلغاء الطلب غير المكتمل يسترد المبلغ مرة واحدة. لا يسمح النظام بإلغاء الطلب المكتمل بهذه الآلية.
- ربط مزود خدمات API وتنفيذ الخدمات آليًا ليس فعالًا بمجرد رفع الواجهة؛ يحتاج مزودًا حقيقيًا، مفاتيح آمنة، ومطابقة حالات ونتائج المزود.
- نص إقرار JTAG تحذير تشغيلي عام وليس بديلًا عن مراجعة قانونية محلية.
- لا تختبر على أموال حقيقية قبل اختبار صلاحيات RLS، الشحن، التحويل، الرتب، إلغاء الطلب، والاسترداد في مشروع تجريبي.

## الملفات

- `index.html` — الواجهة.
- `style.css` — التصميم المتجاوب.
- `app.js` — سلوك الواجهة.
- `config.js` — عنوان Supabase والمفتاح العام فقط.
- `schema.sql` — الجداول وسياسات RLS والإجراءات المالية والرتب وأرقام الطلبات.
- `supabase/functions/username-login/index.ts` — دالة تسجيل الدخول باسم المستخدم.
